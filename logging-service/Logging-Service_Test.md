# 📝 Logging Service - Test Coverage Report

## 1. Overview
The **Logging Service** acts as the central hub for all logs generated by OmniCharge microservices. It listens to a RabbitMQ queue (`logging.events.queue`), processes structured `LogEvent` payloads, persists them to a MySQL database, and writes formatted logs to rolling files grouped by service.

## 3. Key Enhancements & Validations
- **Rolling File Policy Implemented**: Originally absent, the `LogFileWriterService` was modified to dynamically check file sizes. Files exceeding **10MB** are automatically rolled over appending the current date and an incrementing index (e.g., `api-gateway-2026-03-24.0.log`), fulfilling the initial architecture requirements.
- **Fail-Safe Mechanism**: The `LogPersistenceServiceTest` guarantees that if the centralized MySQL DB goes down, the RabbitMQ consumer (`LogEventConsumer`) gracefully handles the exception and still ensures the `LogFileWriterService` writes the log to disk.
- **Microservice Trace Propagation**: Verified that `traceId` and `spanId` fields map cleanly from the cross-service `LogEventPublisher` into the centralized `LogEntry` table and files.
